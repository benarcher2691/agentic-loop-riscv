- [x] **Hardware fix: hold reset until the block RAM is ready.** On the real iCE40 the block RAM contents are not readable for a while after configuration (Lattice: several microseconds; the reference design waits 2^16 clocks). `Clockworks` releases `resetn` after 16 CLK cycles (1.3 µs), so on the board the CPU fetches garbage from the program BRAM and executes it: LEDs stay dark and no banner is sent, although every simulation passes (simulated BRAM is ready at time 0). Fix in `rtl/clockworks.v`: add `parameter RESET_CYCLES` — **65536 by default (hardware)**, and `16` under `` `ifdef FAST_SIM `` (so every bench keeps its timing) — implemented as a counter that sticks at its terminal value. Update `tb/clockworks_tb.v`: keep the existing 16-cycle checks (FAST_SIM) and add one instantiation with `#(.RESET_CYCLES(64))` that checks `resetn` is low for exactly 64 CLK cycles then high forever. Also confirm (with a check) that `Processor` holds `PC = 0` and `state = FETCH_INSTR` and that `SOC` holds `LEDS = 0` while `resetn` is low. No other functional change; `make check` must stay green (equiv included).
